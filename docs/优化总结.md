这份文档记录 2026-09-14 这一轮改动的**来龙去脉**：每一项要解决的问题、实现上的取舍、怎么验收的、踩过哪些坑。面向的是以后接手这份代码的人（也包括几个月后的我自己）。

## 三、胜率 / 目差曲线

**口径只算一次。** 宿主 `compactCurve(game)` 把两条曲线算好塞进 `/go-sensei/review` 的载荷（`payload.curve = { winrate[], score[] }`，下标 i ＝第 i+1 手之后），浏览器只负责画。之所以不在客户端算：棋谱里 `WV[]` 是白方视角、`DM[]` 是黑方视角、`LZ[]` 是落子者视角、注释里的胜率又是一套（见记忆里的 LZ 数据约定），分散到三处视图去算迟早会算出三条不同的曲线。

- **统一黑方视角**：讲棋时「谁领先」需要一个固定参照，混用视角最容易讲反。
- **缺数据就断开**，不连线、不猜：`null` 处把折线拆成多段 polyline。
- **轴**：胜率 `[100, 50, 0]`；目差关于 0 对称、取整到 10 目档（均势区胜率刻度很陡，判断"亏了多少"要看目差）。
- **交互**：问题手在曲线上点小色点（紫/红/橙＝大恶手/失误/不精确），当前手一条竖虚线 + 游标点，点图上任意位置跳到那一手；表头显示当前手数值。
- **折叠态跨视图共享**（`curveWinrate` / `curveScore` 进模块级 store），和棋盘的其他开关一样。

## 四、追问配图（`go_draw_diagram`）

**为什么非得自己开一条 HTTP 路由。** DSH 聊天区把 Markdown 图片渲染成 `<img>` 只有一个条件：目标是**绝对 http(s) 地址**。相对路径、`/C:/...`、`//host/...` 一律塌成 alt 文字；`/api/file?path=` 那条内建路子在 Windows 上会把 `/C:/...` 解析成 `C:\C:\...`，不可靠。所以插件注册 `/go-sensei/diagram`（不鉴权），工具直接返回 `![说明](http://<host>/go-sensei/diagram?...)`。

- 渲染是**纯函数**（`src/diagram.js`：木纹渐变、黑白子、编号棋子描边、标注取对比色、图注深棕铺满整块——否则深色聊天底上看不见图注），路由只是把参数翻成 `renderBoardSvg(spec)`，无状态、不写临时文件、不需要联网。
- **参数约定**：`path` / `move`（基准局面）/ `seq`（`F16` 自动轮转，或 `B:F16` 显式定色）/ `marks`（`triangle:` `square:` `circle:` `cross:` `label:`）/ `cap`（图注）/ `w`。缺 `path` → 400，文件不存在 → 404。
- **主机名动态纠正**：base URL 在挂载时用 `webServer.host/port` 填（`0.0.0.0` 映射成 `127.0.0.1`），每个请求再用 `req.headers.host` 纠一次 —— 用 `localhost` 还是局域网 IP 打开界面都能显示。没有 `webServer`（纯 CLI 组合）时工具**明确报错，不编造 URL**。
- **配图靠模型主动调工具**，所以指令写在两处：人设第 5 条「配图讲解」，以及追问语本身（整页/右侧栏点一行或点交叉点得到的追问语末尾都写着「画一张变化图」）。只写人设会被长对话稀释。

## 五、下方面板瘦身

面板经历了两次减法：先去掉棋盘（`88ab934`），再去掉问题手列表（`86943ca`）。现在是：**路径输入 → 读取问题手 → 状态行（停在第几手 · 坐标 · 难度 · 手数/问题手数）→ 两条曲线**，0 个问题手时保留一行原因说明（无分析数据 / 补算失败），否则用户只会看到一个空的 0。

- 理由：输入框下方地方小、又要给输入框让位；列表和棋盘在整页与右侧栏都有足够空间，重复摆一份只会挤。
- 连带删掉了 `insert()` / `pickCandidate()`：**面板不再往输入框插话**。追问入口统一成「点一行 / 点交叉点 → 复制到剪贴板」（整页与右侧栏都没有 inputActions，本来也只能复制），粘到输入框回车即可。

## 六、排版：讲解必须留在屏内

这是用户这次最硬的要求。左侧栏整页的做法是**让棋盘宽度跟着视口高度走**，而不是给棋盘一个固定尺寸：

| 视图 | 棋盘宽度 | 讲解框 |
|---|---|---|
| 左侧栏整页 | `min(760px, max(340px, 100vh - 340px))` | `min-height: 118px`，`max-height: 240px` |
| 右侧栏文档 | 左列 `flex: 2 1 320px`（上限 480px） | `min-height: 118px`，`max-height: 260px` |

减掉的那部分是页头 / 控件条 / 状态行 / 图例 / 讲解本身的固定开销；窗口矮时棋盘自己收，但**保底 340px**，不会缩到看不清。整页在 `max-width: 860px` 时退回单列并把棋盘居中。讲解、图例、手数小结在底部合成一块（`.dgs-page-foot` / `.dgs-doc-foot`），不再和问题手列表抢高度。

**右侧栏走的不是这条算式**（2026-09-14 修正）：**侧栏高度 ≠ 窗口高度**，第一版拿 `100vh - 560px` 去猜，在 807px 高的窗口里恰好撞上 280px 下限 —— 棋盘被压小，曲线却照旧堆在棋盘下方，讲解的"位置"是拿棋盘尺寸换来的，用户看一眼就说「没变」。现在右侧栏与整页同一套分工：左列棋盘 + 控件条、右列两条可折叠曲线（`.dgs-doc-inner` 用 `display:flex; flex-wrap:wrap`，两列宽度比例 `2:1`，`justify-content:center`），侧栏拖到 430px 以下曲线自动折回棋盘下方；讲解靠**列宽预算**留在屏内，而不是靠窗口高度。

## 七、怎么验收的

1. **单测**：`node --test --test-isolation=none test/*.test.mjs` → **219 项全绿**；`npm run check` 通过。
2. **宿主真机**（改了 `index.mjs` / `src/*.js` 必须重启 `dsh web`）：比对进程启动时间与源文件 mtime，确认新代码在跑；再直接打路由：
   - `/go-sensei/review?path=…` → 149 手棋谱 0.2s 返回 149 点曲线、20 个候选，与独立解析逐点一致；
   - `/go-sensei/diagram?…` → 200 `image/svg+xml`，缺 `path` → 400、文件不存在 → 404。
3. **渲染验收**（不改用户浏览器的前提下看"长什么样"）：`review-check/_readme-shots.mjs` 用真的 `client.js`（React 桩 + slots 桩）跑出三处视图，数据来自运行中的宿主路由，再序列化成 HTML 交给无头 Chrome 截图。本 README 的四张配图就是这么来的（演示棋谱由 `test/fixtures/real-analysis.sgf` 现场生成：中性棋手名 + 几句老师讲解，LZ 分析数据原样保留）。

## 八、踩过的坑（都是真踩的）

| 现象 | 原因 | 教训 |
|---|---|---|
| 预览截图"看着像回事"，其实毫无布局 | 预览脚本没注入插件自己的 CSS：`ensureStyles()` 在 Node 里因没有 `document` 被 try/catch 静默吞掉 | 预览必须传 document 桩捕获 CSS 再拼进 HTML；`_curves-preview.mjs` 至今没修，**不能**拿它做配图 |
| 截图脚本找不到「展开」按钮 | 遍历函数 `walk()` 遇到字符串直接 return，从不 push → `texts()` 永远是空串 | 遍历 React 树时**把字符串/数字也当节点** |
| 棋盘整张缩成左上角一小块 | 序列化时把属性名一律 kebab 化，`viewBox` 被写成 `view-box` | 只翻 React 会翻的属性名，`viewBox` 原样保留 |
| 配图的图注不显示 | 路由参数名是 `cap`，我传的是 `caption` | 生成前先对一眼路由读的是哪个键 |
| 右侧栏文档截图永远是空壳 | 文档正文在 effect 里 fetch，且 effect 每次运行都 `setData(null)` | 顺序是 render → await → render，**拿到第二次的树立刻截图**，再渲染一次就空了 |
| 中文注释全变乱码 + BOM | 用 PowerShell 的 `Get-Content -Raw \| Set-Content -Encoding utf8` 改 UTF-8 源码 | 改文件一律用编辑工具（这条记忆里早写过，还是犯了） |
| 配图里三角形压在编号「1」上 | 同一个点既编号又标三角形 | 让三角形标 AI 首选、编号从后续应接开始 |
| **改了 CSS，界面一点没变**（用户报「右侧栏我实际看没变呀」） | `ensureStyles()` 见 `<style id=…>` 已存在就 `return`。客户端插件是**热重载**：模块重跑，但上一次插进 `<head>` 的 `<style>` 不会消失，于是新 CSS 永远不生效 —— 除非手动刷新页面 | 注入样式必须**比对 textContent 并覆盖**；判定"新代码在不在跑"要看 DOM 结构（如 `.dgs-doc-main` 是否出现），**不能只看界面** |
| 侧栏棋盘小得没道理、曲线还压在棋盘下方 | 用 `100vh - 560px` 猜侧栏高度（侧栏高度 ≠ 窗口高度），恰好撞上 280px 下限 | 侧栏用 flex 折行 + 列宽比例，别用视口高度换算 |
