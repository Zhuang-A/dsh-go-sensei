v0.2.13：DSH 0.2.0 适配 + 配图形态自适应 + 一轮安全加固

这一版把「DSH 0.2.0 到底能不能用」从检查结论变成代码与声明，并按安全复查加固了写盘与执行面。

**适配 DSH 0.2.0（官方桌面端内核 0.2.0-rc.2 实测）**
- 全链路可用：7 个工具注册成功、客户端 4 处插槽 active、面板路由复用 GUI 鉴权闸门、补算写回 `-sensei` 副本正常
- 清单补 `dsh.manifestVersion: 1`；`0.2.0-rc.2` 记为 compatible；README 增加「兼容性（DSH 版本）」一节
- 记一笔：0.2.0 的兼容闸门只认 `peerDependencies`，`engines.dsh` / `compatibility.dshReleases` 都是声明性字段

**配图形态按页面来源自适应（修掉桌面端空白图）**
- 桌面端页面跑在 `dsh-app://app` 上，宿主 cookie 由外壳进程持有、注册为 `SameSite=Strict` 且不下发给页面 —— 指向 `http://127.0.0.1:<端口>` 的绝对图片地址必然 401。改为：桌面端把 SVG 落盘到 `<棋谱目录>/.go-sensei/diagram-<指纹>.svg`，用**本机路径**出图（界面会改写成带鉴权的 `/api/file`）
- 浏览器界面仍用直链，且主机名改用**页面自己的 origin**（局域网 / 换端口打开不再指向 127.0.0.1）
- 面板五处请求与「对话挂载时的一次性上报」都带 `x-go-sensei-page`；宿主按会话记账（LRU 32），非法上报一律不采信
- 配图装配收敛到 `src/diagram-spec.js`：工具与面板路由共用同一份推导，不再各算一遍颜色/手数

**安全复查（DeepSec L3 + VulnClaw）后收紧**
- **引擎路径覆盖默认关**（新配置项 `allowEnginePathOverride`，默认 `false`）：`engineDir` / `kataGoPath` / `kataGoConfig` / `kataGoModel` 是模型可传入参，最终会走 `subprocess.spawn` 与文件读取 —— 改为只有配置显式打开才生效；关着时入参被忽略并在结果里写明"已被忽略"
- 显式 `kataGoPath` 只接受 KataGo 发行名（`katago` / `katago.exe` / `katago-opencl.exe` 这类）且必须是普通文件；`engineDir` 里的同名**目录**不再被当成引擎；配置文件读取加上限（256 KB），避免一次调用把宿主内存拖垮
- `/go-sensei/diagram` 的包含校验移到 `stat` 之前：去掉"文件存不存在"的可区分信号
- 配图文件名只认十六进制指纹，防止 `..` 越出 `.go-sensei/`
- `go_export_report` 的报告目标必须是 `.md`，并拒绝覆盖棋谱（源谱与 `-sensei` 副本）
- `.gitignore` 忽略 `-sensei` 副本与 `.go-sensei/`（含真实野狐 ID，公开仓库不该收）

**测试** 286 → 306：新增 manifest / diagram-spec 两组契约测试，以及桌面端落盘、页面来源分桶、引擎准入闸门、报告目标等用例
